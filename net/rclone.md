# Руководство по использованию ratclone и настройке облачных хранилищ

[**ratclone**](https://github.com/SyscallBrain/ratclone) — это терминальный двухпанельный файловый менеджер для `rclone` с управлением в стиле Vim и поддержкой фоновой передачи файлов.

---

## 1. Установка и запуск

Для работы требуется **Linux** (`x86_64` или `aarch64`) и **`rclone` версии 1.68.0 или новее** (для авторизации через браузер внутри приложения — **v1.75.0+**).

### Обновление rclone (актуально для Debian/Ubuntu)
```bash
sudo -v ; curl https://rclone.org | sudo bash
```

### Установка ratclone
* **Arch Linux (AUR):**
  ```bash
  paru -S ratclone-bin
  ```
* **Debian / Ubuntu:**
  ```bash
  sudo apt install ./ratclone_*_amd64.deb
  ```
* **Fedora / RHEL:**
  ```bash
  sudo dnf install ./ratclone-*.x86_64.rpm
  ```
* **Сборка из исходников (требуется Rust 1.88+):**
  ```bash
  cargo install --locked ratclone
  ```

### Варианты запуска
```bash
ratclone                        # Запуск с вашими аккаунтами
ratclone --demo                 # Безопасный демо-режим с тестовыми данными
ratclone --rclone ~/bin/rclone  # Указать путь к бинарнику rclone вручную
```

### Исправление отображения иконок (символ `  `)
Если вместо иконок отображаются «квадратики»:
1. **Быстрый способ:** откройте настройки в `ratclone` клавишей `,` и переключите параметр `Icons` с `nerd` на `ascii` (или добавьте `icons = "ascii"` в `~/.config/ratclone/config.toml`).
2. **С иконками:** установите любой шрифт из семейства **Nerd Fonts** (например, `JetBrainsMono Nerd Font`) и выберите его в настройках вашего эмулятора терминала.

## 2. Управление и горячие клавиши

### Навигация и панели

| Клавиша | Действие |
| :--- | :--- |
| `j` / `k` | Вниз / вверх по списку |
| `h` / `l` | Выйти из папки / открыть папку |
| `gg` / `G` | В начало / в конец списка |
| `Tab` | Переключение фокуса между списком аккаунтов и панелями |
| `\|` | Открыть или закрыть вторую панель (двухпанельный режим) |
| `/` | Фильтр файлов в текущей директории |

### Работа с файлами и копирование
* **Через две панели:** откройте вторую панель (`|`), выберите источник и назначение, выделите файлы (`Space` — поштучно, `v` + `j`/`k` — диапазоном) и нажмите **`>`** или **`F5`** для копирования (**`F6`** — для перемещения).
* **Через буфер обмена (Vim-стиль):** выделите файлы, нажмите **`y`** (копировать) или **`x`** (вырезать), перейдите в целевую папку и нажмите **`p`** (вставить).
* **Прочие операции:** `r` — переименовать, `o` — создать папку, `dd` — удалить.

### Вкладки и сервис

| Клавиша | Действие |
| :--- | :--- |
| `T` | Вкладка **Transfers** (прогресс, скорость, выполняемая команда `rclone`) |
| `U` | Вкладка **Space** (анализ занятого места: папки и крупные файлы) |
| `a` / `e` | Добавить новый / редактировать выбранный аккаунт (в списке слева) |
| `,` | Настройки и смена темы оформления |
| `?` | Справка по всем горячим клавишам |
| `q` | Выход (при активных загрузках предложит оставить их в фоне) |

## 3. Подключение различных хранилищ

### А. FTP / SFTP
Нажмите `a` в списке аккаунтов `ratclone` и укажите:
* **Name:** произвольное имя (например, `my-ftp`)
* **Type:** `ftp` (или `sftp`)
* **Host:** адрес сервера или IP
* **Port:** `21` (для FTP) или `22` (для SFTP)
* **User / Pass:** логин и пароль

*Совет: при нестабильной работе FTP добавьте в настройки аккаунта (`e`) параметр `concurrency = 1`.*

---

### Б. Яндекс Диск (решение ошибки `410 - GoneError`)
Встроенный `client_id` в `rclone` заблокирован Яндексом, поэтому при стандартном входе возникает ошибка `[410 - GoneError] Gone`. Используйте один из двух рабочих способов:

#### Способ 1: Собственный OAuth ClientID (через API)
1. Перейдите на [oauth.yandex.ru](https://yandex.ru) и создайте приложение («Для доступа к API или отладки»).
2. В разделе **«Доступ к данным»** добавьте права:
   * `cloud_api:disk.read`
   * `cloud_api:disk.write`
   * `cloud_api:disk.info`
3. Скопируйте полученный **ClientID** и откройте в браузере ссылку:
   ```text
   https://yandex.ruauthorize?response_type=token&client_id=ВАШ_CLIENT_ID
   ```
4. Скопируйте выданный отладочный токен (`y0_...`) и впишите его в `~/.config/rclone/rclone.conf`:
   ```ini
   [yandex]
   type = yandex
   token = {"access_token":"ВАШ_ТОКЕН_y0_...","token_type":"OAuth","expiry":"2027-11-16T00:00:00Z"}
   ```
5. В `ratclone` нажмите `R` для обновления списка файлов.

#### Способ 2: Через WebDAV (по паролю приложения)
1. Создайте пароль типа **«Файлы (WebDAV)»** на странице [id.yandex.ru/security/app-passwords](https://yandex.ru).
2. Создайте аккаунт в `ratclone` (`a`):
   * **Type:** `webdav`
   * **URL:** `https://yandex.ru`
   * **Vendor:** `other`
   * **User:** логин Яндекса (без `@yandex.ru`)
   * **Pass:** сгенерированный пароль приложения

---

### В. Google Drive (и решение ошибки `invalid_scope`)
1. Создайте аккаунт через `a` в `ratclone` или команду `rclone config`.
2. **Type:** `drive`.
3. **Важно:** при настройке **внутри формы `ratclone`** в поле `scope` указывайте слово **`drive`** (или оставьте поле пустым). Ввод цифры `1` (как в консольном `rclone config`) вызовет ошибку `400: invalid_scope {invalid=[https://googleapis.com]}`.
4. Пройдите авторизацию в открывшемся окне браузера.

---

### Г. Публичные HTTP-зеркала (например, зеркало Linux Яндекса)
Позволяет просматривать и скачивать файлы напрямую с открытых веб-индексов:
* **Type:** `http`
* **URL:** `https://yandex.ru`

---

### Д. Другие поддерживаемые протоколы и виртуальные бэкенды
* **Сетевые протоколы:** `webdav` (Nextcloud, Mail.ru), `nfs`, `smb`, `hdfs`.
* **Объектные хранилища (`s3`):** Yandex Object Storage, VK Cloud, Selectel, AWS S3, Cloudflare R2, MinIO и др.
* **Потребительские облака:** `onedrive`, `dropbox`, `mega`, `pcloud`, `mailru`.
* **Виртуальные обёртки:**
  * `memory` — виртуальный диск в оперативной памяти (RAM) для тестов и замеров скорости (очищается после закрытия программы).
  * `union` — объединение нескольких облаков в один общий диск.
  * `alias` — быстрый ярлык на глубоко вложенную папку.
  * `compress` — прозрачное сжатие файлов на лету.
  * `chunker` — автоматическая нарезка больших файлов на части.

## 4. Прозрачное шифрование (`crypt`)

Позволяет создать зашифрованный контейнер поверх любой папки в облаке (имена файлов, папок и их содержимое шифруются на лету).

1. Создайте пустую папку в целевом облаке (например, `gdrive:Vault`).
2. Запустите в терминале мастер настройки:
   ```bash
   rclone config
   ```
3. Выберите `n` (New remote), задайте имя (например, `gdrive-crypt`) и тип **`crypt`**.
4. Укажите параметры:
   * **Remote to encrypt/decrypt:** `gdrive:Vault`
   * **How to encrypt the filenames:** `1` (полное шифрование имён файлов)
   * **Encrypt directory names:** `1` (шифровать имена папок)
   * **Password / Salt:** задайте или сгенерируйте (`g`) оба пароля и **обязательно сохраните их в менеджер паролей**.
5. Сохраните (`y`) и выйдите (`q`). В `ratclone` появится диск `gdrive-crypt`, где файлы отображаются в обычном виде, тогда как в самом облаке лежат зашифрованные данные.

---

## 5. Хранение паролей и безопасность

* Все конфигурации, токены и обфусцированные пароли хранятся в файле:
  ```text
  ~/.config/rclone/rclone.conf
  ```
  *(Проверить точный путь: `rclone config file`)*.
* **Защита конфига мастер-паролем (AES-256):** выполните `rclone config` → `s` (Set configuration password) → `a` (Add password). После этого файл `rclone.conf` будет зашифрован, а при запуске `ratclone` будет запрашиваться мастер-пароль. Сделайте резервную копию этого файла в надёжное место.

---

## 6. Просмотр текстовых файлов и предпросмотр

В `ratclone` нет встроенного просмотрщика содержимого файлов. Используйте альтернативы в соседнем окне терминала:

1. **Чтение без скачивания на диск (`rclone cat`):**
   ```bash
   rclone cat yandex:notes/todo.txt | less
   ```
2. **Через `/tmp` или `memory`:** откройте `/tmp` во второй панели `ratclone`, скопируйте туда файл (`F5`) и откройте любым редактором (`less /tmp/file.txt`).
3. **Монтирование облака как обычной папки (`rclone mount`):**
   ```bash
   mkdir -p ~/clouds/gdrive
   rclone mount gdrive: ~/clouds/gdrive --vfs-cache-mode writes --daemon
   ```
   После монтирования файлы можно просматривать и редактировать в любых программах и файловых менеджерах (`yazi`, `ranger`, `mc`).

## 7. Собственный Client ID для Google Drive (снятие лимитов скорости)

Встроенный `client_id` в `rclone` общий для всех пользователей, поэтому при активном копировании множества мелких файлов Google может временно ограничивать скорость (`403 Rate Limit Exceeded`). Создание собственного бесплатного OAuth-приложения в Google Cloud полностью снимает это ограничение.

1. Перейдите в [Google Cloud Console](https://google.com) и создайте новый проект (например, `rclone-personal`).
2. В меню слева откройте **APIs & Services → Library**, найдите **Google Drive API** и нажмите **Enable**.
3. Перейдите в **APIs & Services → OAuth consent screen**:
   * Выберите тип **External** и нажмите **Create**.
   * Заполните обязательные поля: название приложения (например, `rclone`) и ваш email в полях *User support email* и *Developer contact information*.
   * На вкладке **Audience** (или *OAuth consent screen*) нажмите **Publish App** (переведите статус из *Testing* в *In production*, чтобы токен не сбрасывался каждые 7 дней) **или** добавьте свой Gmail в список **Test users**.
4. Перейдите в **APIs & Services → Credentials → Create Credentials → OAuth client ID**:
   * Выберите **Application type:** `Desktop app`.
   * Задайте любое имя и нажмите **Create**.
   * Скопируйте выданные **Client ID** и **Client Secret**.
5. Внесите их в существующий профиль Google Drive (через `e` в `ratclone` или в `~/.config/rclone/rclone.conf`):
   ```ini
   [gdrive]
   type = drive
   client_id = ВАШ_CLIENT_://googleusercontent.com
   client_secret = ВАШ_CLIENT_SECRET
   scope = drive
   ```
6. Обновите токен авторизации командой `rclone config reconnect gdrive:` (или переавторизуйтесь в браузере при запуске `ratclone`).

## 8. Автоматическое монтирование облаков через systemd

Чтобы облака (включая зашифрованные `crypt`-диски) автоматически подключались как обычные папки при входе в систему и были доступны в любых программах:

1. Создайте папку для точки монтирования (например, для Google Drive):
   ```bash
   mkdir -p ~/clouds/gdrive
   ```
2. Создайте директорию для пользовательских юнитов `systemd` и файл сервиса:
   ```bash
   mkdir -p ~/.config/systemd/user
   nano ~/.config/systemd/user/rclone-gdrive.service
   ```
3. Вставьте следующую конфигурацию (замените `gdrive` на имя вашего аккаунта из `rclone.conf`):
   ```ini
   [Unit]
   Description=Rclone Mount for Google Drive
   After=network-online.target
   Wants=network-online.target

   [Service]
   Type=notify
   ExecStart=/usr/bin/rclone mount gdrive: %h/clouds/gdrive \
       --vfs-cache-mode writes \
       --vfs-cache-max-age 24h \
       --dir-cache-time 5m \
       --umask 002
   ExecStop=/bin/fusermount3 -u %h/clouds/gdrive
   Restart=on-failure
   RestartSec=10

   [Install]
   WantedBy=default.target
   ```
   *(Примечание: если в системе установлена старая версия FUSE, замените `fusermount3` на `fusermount`; проверить путь к `rclone` можно командой `which rclone`).*

4. Включите автозапуск и запустите службу прямо сейчас:
   ```bash
   systemctl --user daemon-reload
   systemctl --user enable --now rclone-gdrive.service
   ```
5. Проверить статус работы или посмотреть логи при ошибке:
   ```bash
   systemctl --user status rclone-gdrive.service
   ```

*Совет: если файл `rclone.conf` защищён мастер-паролем, добавьте в секцию `[Service]` строку `Environment="RCLONE_CONFIG_PASS=ваш_мастер_пароль"`, чтобы сервис мог монтировать диск в фоне без ручного ввода пароля.*
